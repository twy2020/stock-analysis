# 消息中心与反馈工单

## 设计与实施顺序

1. 保留 feedback 原始意见、对话快照、图片；增加 feedback_replies、center_receipts、announcements 三张表，不重写历史反馈。原 NEW/REVIEWING/RESOLVED 分别展示待处理、处理中、已关闭。
2. 用户消息中心左侧为系统消息、反馈、历史反馈。反馈提交创建工单；历史反馈分页、搜索，详情展示原始意见和时间顺序回复。未关闭可继续反馈，关闭由后端拒绝后续回复。
3. 管理员工单页提供状态统计、搜索、未读过滤、分页、会话记录、回复、关闭和重新开启。系统消息页提供发布和撤回，仅本组织可见。
4. 未读游标按用户、类型、记录保存。工单只标记已展示的回复序号；旧读取请求不得覆盖更新的游标。用户未读为管理员的新回复/状态变化；管理员未读为新工单/用户补充。
5. 15 秒前台轮询未读摘要，页面不可见时不发请求；打开详情后明确提交已读。切换账号清空所有状态，迟到请求不得带入另一个账号。
6. 对话快照默认折叠，列表为紧凑行式，长文本省略，详情和列表各自滚动；手机端左侧导航缩成顶部分段导航。最小字号 12px，使用 Apple 风格轻质层级和明确焦点。

## 接口边界

- 用户：GET /feedback、/feedback/:id，POST /feedback/:id/replies、/read；读取/已读严格限定 owner。
- 管理员：复用 /admin/feedback 列表、详情、PATCH 状态，增加 POST /replies、/read；限定组织与 ADMIN。
- 消息：GET /announcements，POST /announcements/:id/read；管理员 POST /admin/announcements、PATCH /:id（撤回）。
- 摘要：GET /message-center/unread 返回 system、feedback；管理员 /admin/feedback/stats 返回状态与未读统计。
- 所有写请求复用 CSRF 防护，回复纯文本输出、限制 5000 字；不记录凭据。反馈附件仍按原校验处理并受访问权限约束。

## 验证与发布

先验证工单生命周期、旧游标不会漏未读、跨用户和跨组织访问隔离、公告与已读隔离，再运行现有反馈/审计回归及前端交互测试、生产构建。后台重启前检查运行中任务并备份 SQLite；使用既有容器网络。只部署通过验证的最终版本。
