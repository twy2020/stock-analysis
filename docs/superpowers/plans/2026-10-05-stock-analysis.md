# Stock Analysis Implementation Plan

**Goal:** Deliver a runnable stock research agent whose calculations belong to a data engine.

**Architecture:** Market API -> stock-data-engine -> authorized Core tools -> SaaS
durable message artifacts -> Vue stock renderer. MCP and HTTP share the engine dispatcher.

**Tech Stack:** Flask, httpx, pandas/numpy, Python AST, LangGraph, Vue 3, ECharts.

**Spec:** ../specs/2026-10-05-stock-analysis-design.md

## Global Constraints

Use separate stock-analysis Docker resources. RAG defaults off. Preserve existing
changes. No model-generated numerical series. All results retain source dates,
units, scope and limitations. Execute inline in the authorized current session.

Artifacts use `data.stockArtifact` inside the existing Core tool envelope.
`datasetRef` is generated by the engine; SaaS accepts references only from successful
engine tool artifacts. Dataset reads/annotations require the same full scope.

## Verified Deployment

The stock stack runs at ports 18110 (chat) and 18210 (Core), with independent volumes,
credentials and network. Core health probes carry a service token. Existing Docker
network 192.168.0.0/20 overlaps the market LAN; an authenticated optional Windows
host relay resolves this without changing other stacks. Its startup marker and
credentials remain private. See the root README for direct versus relay operation.

Engine tests: 11 passed. Core tests: 120 passed. SaaS focused tests: 23 passed;
existing chat regression tests: 12 passed.
Frontend tests: 90 passed; production Docker build succeeded. Browser verification
uses real engine-generated analyze/events/backtest datasets, confirms colored canvas
pixels at 1440x1000 and 390x844, no horizontal overflow, row-reference insertion and
three persistent artifacts after reload. Screenshots/report are in artifacts/verification.
Core's authorized stock_query dispatcher also executed a real snapshot filter and
mean aggregation with previewRows=0. No paid model request was used in verification.
